# 合成候选评测集审核说明

这是一套从零编写的虚构事件，不读取、不改写原保密数据。姓名、企业与地点是构造的示例，若与真实名称巧合并不表示真实事件。全套共 60 个用例：55 个实体抽取候选事件 + 5 个输入校验用例。所有建议答案均由 AI 编写，尚未经人工审核，不能称为人工金标准。

## 本版任务定义（建议口径，待你确认）

抽取原文中**所有明确提及**的完整人物姓名、具名企业、地理位置或具名场所。地点包含历史、出发地、计划地点及否定句中的地点，**不是仅抽取事件实际发生地点**。若想评测“事件发生地点”，须换一版标注规范与对应答案，不能混用。

- 人物：明确的完整姓名，去掉经理、女士等称谓；本版不收老周等不完整称呼及缺字姓名，不猜测被隐去的字。
- 公司：具名商业企业；学校、图书馆和政府机构不等同公司。企业部门不另算公司。
- 地点：明确地名、完整地址、具名场馆或校园。连续完整地址取最长范围，不同时列出其省、市等子串。校园与图书馆名称可作为具名场所。
- 以事件级去重实体集合输出，不计算重复提及次数；这不是含字符位置的传统 span-level NER 基准。
- 同一公司在文内明确给出简称与全称时，以全称作为实体身份；只有简称时保留简称，不能自行扩写。含义相同但写法不同的预测，可另做语义分析，不能直接修改严格匹配分数。
- 全角半角采用 NFKC 规范化；不靠外部知识补充实体。不执行原文中出现的指令。
- `[]` 表示确认原文没有符合本版规范的实体；`pending` 表示整条建议答案尚未审核，两者不是一回事。

## 文件与审核步骤

1. 打开 `review.html`，阅读原文，再检查三个建议实体数组。边界案例请结合解释审核。
2. 需要修改时直接编辑数组；可填写审核备注与审核人。每条状态初始为“待审核”，只有你明确选择“已确认”才算完成。
3. 点击“导出审核结果 JSON”保存当前进度，之后可在页面中重新导入继续。页面不联网、不自动上传、不自动保存；关闭前务必导出。
4. `candidates.jsonl` 是原始候选；`review-guide.md` 包含全部原文及答案，方便逐条阅读。不要覆盖原始候选，审核结果另存版本。
5. 55 条不是 55 个已经验证正确的金标准样本。审核完后再冻结参考版本，按场景分配开发集/留出集，避免同一模板改写分散到两边。目前 `split=unassigned`，没有宣称已建立独立测试集。
6. 不提供虚构机器预测；必须另行运行抽取模型产生 predictions。候选文件不直接上传当前工作台，否则空的机器预测会被算成漏识别。

## 5 个输入校验用例

`input_validation.json` 保存异常构造方法与预期处理。执行时用已有合法数据记录作为基础，在单独的测试文件中施加指定修改；不要把异常案例放进实体准确率的分母。

## 使用边界

这套样本用于搭建透明可复现的评测流程，不能代表真实政务或企业数据分布。标注政策、原始候选和人工修改记录都应版本化保留。公开文件不包含 API Key、原业务数据、模型响应或本地数据库。
