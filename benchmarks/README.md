# EvalPilot 评审验证

本目录的 judge_candidates_v1.json 是公开合成的开发候选集，不是已经人工确认的测试集，也不是原抽取模型的训练数据。

## 使用

在项目根目录运行：

    .venv\Scripts\python.exe scripts/check_judge_benchmark.py

默认离线，不消耗 API；只能验证规则路由及候选答案比对。若要对 LLM 做实验，显式加 --live，并用 --output 指定不同结果文件。接口参数从本地 .env 加载，输出不包含密钥。

## 人工标准确认与实验约束

1. 在查看模型答案前确认 expected 中的语义结论、主标签和是否应转人工。null 结论表示口径未定，此项不评分。
2. 多实体案例在本候选集只检查字段主标签集合；实体关联正确性仍需独立核对，不能把该分数当作完整诊断准确率。
3. 人工确认后另存冻结版本，记录确认人、日期、标注规范；不要直接拿开发中反复调整的样本当独立留出测试集。
4. 对照实验保持输入、参考、模型、门禁和运行参数不变，只改变评审 Prompt。保存数据哈希及结果。
5. 比较自动接受覆盖率、已接受结果与人工标准的符合情况、错误放行案例、待复核量、耗时和 Token。候选标准符合度不是人工验证准确率。

目前脚本已记录数据哈希和门禁版本。真实 LLM 对照实验、人工标准确认及独立留出集尚待完成。数据规模不支持推断生产环境效果。

## 运行时门禁

semantic-gate-v1 保留原有结构、引用及实体覆盖校验，新增标签与关联形状、字段结论矛盾、显式简称证据、无原文依据声明的字面反证检查。失败时保留模型建议及 gate_errors，转人工。通过不代表语义已证明正确；规则可能保守拒绝有效结果，需用人工标准评估。

不恢复未经校准的 0.90 自报置信度阈值。不改变严格 TP/FP/FN，不重新评审历史任务。

## A/B 试跑

运行 scripts/run_prompt_ab.py --live 可调用本地配置的接口；不加 --live 为离线流程检查。A 保持当前生产指令，B 只追加实体关联顺序与一致性自检，不改变 JSON schema、模型参数或门禁。脚本按案例交替 AB/BA 顺序，输出到 benchmarks/ab_runs/时间戳，保存两份 Prompt、数据哈希、模型配置、原始响应、校验结果和报告。候选集中只有 4 个双侧差异案例会调用 LLM，共 8 个初始请求；服务异常重试可能增加次数。

当前阶段仅为候选样本试跑，不能用于宣布人工验证准确率，不能根据一次 4 例实验选择生产版本。正式实验需补齐人工确认的实体关联预期，冻结版本并使用独立留出集。生产默认仍为 A。

新的规则定义对照实验见 p0_p1_design.md。运行参数 --design definitions；旧版步骤对照实验保持 --design steps。每次保存到独立时间戳目录，离线试跑不作为模型效果结果。
