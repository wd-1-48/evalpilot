## 如何重放

按主 README 启动服务，上传 XLSX，版本填写 `city-calls-sim-v2`。文件中的 `model_version` 与导入值必须相同。先不启用外部评审运行，再使用同一数据集新建启用 LLM 的运行，比较报告与待复核队列。

相同代码和标注口径下，可复核严格计数：姓名 TP/FN/FP 为 166/39/65，公司为 121/24/13，地点为 138/52/37；事件全对 60/200。LLM 返回内容、延迟及通过校验数量可能变化，不能承诺重现 54 个通过、0 个待复核。耗时取自单次运行，不保证重放时一致。

## 数据来源与口径

数据从零编写，覆盖 40 种居民诉求，每种 5 条，包括欠薪、物业、噪音、供暖、消费退款、出行与公共设施。姓名、公司、城市和具体场所为虚构示例，不对应真实投诉；未复制原始信访业务记录。

`predicted_*` 是人为构造的机器识别结果；`reference_*` 是 AI 编写的建议答案，未经独立人工审核。样本含 60 条正确对照、五类错误各 25 条，以及 15 条遗漏加多识别的混合错误。180 条出现地点、160 条出现人名、135 条出现公司，其中 105 条同时包含三类实体。

- 人名只收明确姓名；被告、原告、居民、司机、工作人员等称谓不算人名。
- 公司收具名商业企业，保留分支机构的完整名称；企业名称里的地域字样不另算地点。
- 地点收原文明示的地名、连续完整地址与具名场所，连续地址取最长范围，不重复列出其市、区等子串；交通起终点均保留。
- 按事件去重，不猜测缺失实体。`[]` 表示对应类别无实体。
- `simulation_scenario`、`simulation_note` 仅说明预设造错方式，不是模型评审结论，不应作为独立评审的答案提示。

## 结果解释与溯源

两份报告保持导出原文不变：

- 未启用 LLM：版本标签 `test-v1`，任务 `b9fcdaa139bf4757a517cb2455c7e8d3`，请求 0 次，规则结论 546，待复核 54，人工确认 0。
- 启用 LLM：版本标签 `222`，任务 `d6f10eccd3ca4d569baafffb3d03590f`，请求 54 次，规则结论 546，LLM 自动通过校验 54，待复核 0，人工确认 0。

启用运行使用 `deepseek-flash`，请求明确设置 `thinking: {type: disabled}`，输出上限保持 4096 tokens。模式信息由对应本地任务的诊断记录核对；报告本身没有展示该参数。代码仅对 DeepSeek 模型添加此模式参数，其他供应商保持原行为。

待复核字段从 54 降至 0，表示本次所有未决字段均获得通过现有校验的诊断，不等于模型准确率 100% 或人工成本降低 100%。人工工作可以转为抽检，但本次没有人工确认记录，也未测量抽检工时。

累计耗时为 8.96 秒和 76.54 秒；字段 P95 分别为 17.26 和 4129.77 毫秒。严格指标相同，因为输入预测、参考答案及统计口径相同，语义诊断不修改严格计数。单次运行不能证明可泛化的模型质量或固定延迟收益。
